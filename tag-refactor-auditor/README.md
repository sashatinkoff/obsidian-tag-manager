# Tag Refactor & Auditor 1.0.5

Плагин Obsidian для поиска, предпросмотра, пакетного переименования и удаления тегов.

## Установка без npm и сборки

1. Откройте каталог хранилища Obsidian и перейдите в `.obsidian/plugins/`.
2. Создайте каталог `tag-refactor-auditor` (либо замените старую папку этой версией).
3. Скопируйте в него три файла: `main.js`, `manifest.json` и `styles.css`.
4. Перезапустите Obsidian или перезагрузите плагины, затем включите **Tag Refactor & Auditor** в настройках сторонних плагинов.
5. Откройте экран через иконку тегов или палитру команд: **Open Tag Refactor & Auditor**.

`main.js` уже содержит объединённый исполняемый код. Папка `source-modules/` в архиве оставлена для чтения и дальнейшего развития исходников; для запуска плагина её копировать не нужно.

## Функциональность

- Поиск тегов из Markdown и YAML-фронтматтера `tag` / `tags`.
- Просмотр заметок с отрендеренным Markdown-фрагментом, а не исходным синтаксисом.
- Сортировка тегов по названию, по дате создания заметки и по количеству заметок.
- Переименование и удаление выбранного тега во всех затронутых файлах через общую очередь и подтверждение.
- Предпросмотр карточки открывает заметку в новой вкладке.
- Пакетный отчёт и отмена последней операции.
- Настройки лимита предпросмотра, регистра, игнорируемых папок и YAML-атрибута даты создания. Пустой атрибут использует дату создания файла; при заданном атрибуте значения читаются из YAML.

В режиме сортировки по дате тег получает самую позднюю дату создания среди заметок, где он встречается. Источник даты задаётся в настройках YAML-атрибутом; если поле пустое, используется время создания файла. Заметки без корректного YAML-значения при заданном атрибуте учитываются как без даты и не подменяются временем изменения.

Порог упоминаний в каталоге сравнивается с количеством заметок, в которых найден тег. Пустое значение или 0 показывает все теги.

Перед массовой операцией рекомендуется проверить работу на копии хранилища.
