# Tag Refactor & Auditor 1.0.19

Плагин Obsidian для поиска, предпросмотра, пакетного переименования и удаления тегов.

## Установка без npm и сборки

1. Откройте каталог хранилища Obsidian и перейдите в `.obsidian/plugins/`.
2. Создайте каталог `tag-refactor-auditor` (либо замените старую папку этой версией).
3. Скопируйте в него три файла: `main.js`, `manifest.json` и `styles.css`.
4. Перезапустите Obsidian или перезагрузите плагины, затем включите **Tag Refactor & Auditor** в настройках сторонних плагинов.
5. Откройте экран через иконку тегов или палитру команд: **Open Tag Refactor & Auditor**.

`main.js` уже содержит объединённый исполняемый код. Папка `source-modules/` в архиве оставлена для чтения и дальнейшего развития исходников; для запуска плагина её копировать не нужно.

## Функциональность

- Поиск тегов из Markdown и YAML-фронтматтера `tag` / `tags`.
- Просмотр заметок с отрендеренным Markdown-фрагментом, а не исходным синтаксисом.
- Сортировка тегов по названию, по дате создания заметки и по количеству заметок.
- Переименование, удаление, снятие маркировки выбранного тега и добавление нескольких новых тегов в заметки, где встречается выбранный тег, — через общую очередь и подтверждение. При снятии маркировки `#привет` визуально остаётся `#привет`, а символ `#` экранируется обратным слешем (`\#привет`) по синтаксису Markdown Obsidian, поэтому это обычный текст; соответствующая запись удаляется из YAML `tag` / `tags`.
- Предпросмотр карточки открывает заметку в новой вкладке.
- Пакетный отчёт и отмена последней операции.
- Настройки лимита предпросмотра, регистра, игнорируемых папок и YAML-атрибута даты создания. Пустой атрибут использует дату создания файла; при заданном атрибуте значения читаются из YAML.

В режиме сортировки по дате тег получает самую позднюю дату создания среди заметок, где он встречается. Источник даты задаётся в настройках YAML-атрибутом; если поле пустое, используется время создания файла. Заметки без корректного YAML-значения при заданном атрибуте учитываются как без даты и не подменяются временем изменения.

Порог упоминаний в каталоге сравнивается с количеством заметок, в которых найден тег. Пустое значение или 0 показывает все теги.

Перед массовой операцией рекомендуется проверить работу на копии хранилища.


### Форматы дат для сортировки

Поле YAML, заданное в настройках, поддерживает ISO (`2012-10-12`, дата/время), числовые форматы (`12.10.2012`, `12/10/2012`, `2012/10/12`), текстовые названия месяцев на русском, английском, украинском, белорусском, польском, немецком, французском, испанском, португальском, итальянском, нидерландском, скандинавских, турецком, греческом, арабском и тайском языках, а также форматы `2012年10月12日` и `2012년 10월 12일`. Тайские годы Buddhist Era также преобразуются в григорианские, если дата содержит тайское название месяца. Текстовые месяцы распознаются независимо от регистра и диакритики. Для числовых дат с косой чертой `MM/DD/YYYY` используется американский порядок, а для точек и дефисов — `DD.MM.YYYY` / `DD-MM-YYYY`; ISO-формат `YYYY-MM-DD` предпочтителен для однозначности.


## Version 1.0.10

The tag search field now has enough left/right padding to keep text clear of its icons and includes a dedicated clear (×) button. The unmark operation now writes a Markdown escape (`\#tag`) instead of an HTML entity, preserving the visible hash while preventing Obsidian from indexing the occurrence as a tag. The matching YAML `tag` / `tags` entry is still removed.


## Version 1.0.11

В карточку списка тегов добавлена буквенная навигация. Отображаются только буквы, с которых начинаются теги в текущем отфильтрованном списке; регистр не учитывается. Нажатие на букву плавно прокручивает список к первому тегу, начинающемуся с этой буквы.


## Version 1.0.12

Добавлено пакетное добавление нескольких тегов к заметкам, содержащим выбранный тег. Новые теги можно вводить через пробелы, запятые или переносы строк. Если исходный тег находится в YAML `tag` / `tags`, существующее поле расширяется с сохранением других значений и без дублирования тегов. Если исходный тег находится в тексте, новая строка тегов добавляется в конец каждой записи, содержащей исходный тег, перед ближайшим разделителем Markdown `---` либо в конец последней записи. Разделители, переводы строк и кодовые блоки сохраняются. Добавления можно комбинировать с другими действиями в очереди и отменить последнюю пакетную операцию.

## Version 1.0.13

Добавлена вкладка «Массовое управление». На ней можно отфильтровать Markdown-заметки по диапазону дат создания (YAML-свойство из настроек или дата создания файла), выбрать все отображаемые заметки либо снять выделение, просмотреть кратко отрендеренный Markdown, увидеть теги каждой заметки и открыть её в отдельной вкладке. Для выбранных заметок поддерживаются операции добавления нескольких тегов, переименования нескольких тегов по строкам `старый -> новый` и удаления нескольких тегов. Перед записью показывается подтверждение, затем отчёт. Последний пакет доступен для отмены.



## v1.0.14 — массовое управление

Карточки заметок в разделе массового управления не загружаются автоматически при открытии вкладки. Укажите диапазон дат и нажмите «Применить фильтр»; только после этого плагин строит список карточек и предпросмотры. Изменение дат сбрасывает результаты и снова показывает плейсхолдер до повторного применения фильтра.


## v1.0.15 — исправлен ввод даты

При изменении диапазона дат больше не перерисовывается весь экран: нативное поле даты не теряет фокус во время ручного ввода года. Список карточек сбрасывается на плейсхолдер без пересоздания полей ввода; чтобы загрузить заметки, нажмите «Применить фильтр».


### v1.0.16

Проверка диапазона дат выполняется только по кнопке «Применить фильтр». Во время ручного ввода даты плагин не показывает ошибку и не сбрасывает значение поля.


### v1.0.17

В массовое управление добавлен фильтр по тегу с автодополнением по существующим тегам хранилища. Чекбокс «Любые теги» включён по умолчанию и скрывает поле тега; при его отключении можно выбрать конкретный существующий тег. Как и фильтр по датам, изменения применяются только после нажатия «Применить фильтр».


### v1.0.18

Вкладка «Массовое управление» переименована в «Заметки по датам», а заголовок раздела — в «Управление заметками по датам».


### v1.0.19

В разделе «Заметки по датам» добавлена сортировка карточек по дате создания: новые сначала или старые сначала. Для операции «Добавить теги» добавлена опция «Всегда добавлять в атрибуты»: она записывает теги в YAML `tag`/`tags`, а если таких полей нет — создаёт `tags`. Если опция выключена, сохраняется прежнее поведение: без YAML-поля теги добавляются в текст заметки.
