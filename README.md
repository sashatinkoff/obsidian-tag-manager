# Tag Refactor & Auditor 1.0.28

Плагин Obsidian для поиска, предпросмотра, пакетного переименования и удаления тегов.

## Установка без npm и сборки

1. Откройте каталог хранилища Obsidian и перейдите в `.obsidian/plugins/`.
2. Создайте каталог `tag-refactor-auditor` (либо замените старую папку этой версией).
3. Скопируйте в него три файла: `main.js`, `manifest.json` и `styles.css`. Папка `src/` не обязательна.
4. Перезапустите Obsidian или перезагрузите плагины, затем включите **Tag Refactor & Auditor** в настройках сторонних плагинов.
5. Откройте экран через иконку тегов или палитру команд: **Open Tag Refactor & Auditor**.

## Структура исходников

Сборщик не нужен: все файлы — готовый к выполнению JavaScript (CommonJS-модули с `require("./…")` / `module.exports`).

`main.js` самодостаточен: в нём небольшой загрузчик и встроенные без изменений копии всех модулей `src/`. Поэтому для работы плагина достаточно трёх стандартных файлов.

Если положить рядом с `main.js` папку `src/`, загрузчик берёт модули из неё, а не встроенные копии. Так удобно дорабатывать плагин: правите файл в `src/`, перезагружаете плагин, и изменения сразу работают. Ошибки в консоли разработчика при этом указывают на конкретный файл `src/…`. Учтите, что встроенные копии в `main.js` ваши правки не получат. Если `src/` потом удалить, плагин вернётся к коду, встроенному в `main.js`.

```
main.js                   загрузчик + встроенные копии модулей src/
src/
  index.js                собирает класс плагина из миксинов
  constants.js            константы и настройки по умолчанию
  utils.js                склонение, время, числа, applyMixins
  scanner.js              индекс тегов из кэша метаданных
  dates.js                разбор дат создания (ISO, числовые, месяцы на многих языках)
  settings-tab.js         вкладка настроек
  plugin/
    core.js               жизненный цикл, настройки, сканирование индекса
    queue.js              очередь переименований, удалений, снятия # и добавлений
    batch.js              пакетная запись файлов и отмена
  tags/
    tag-name.js           нормализация и проверка имён тегов
    frontmatter.js        поиск и сборка YAML-фронтматтера, значения tag/tags
    changes.js            карта операций по ключу тега
    markdown.js           теги в тексте: обход вне кода и ссылок, замена, поиск
    yaml.js               построчное изменение YAML tag/tags
    add-tags.js           добавление тегов в YAML или в текст записей
    extract.js            все теги заметки из её текста (для окна просмотра)
    posts.js              записи внутри заметки (разделитель ---)
    move.js               перенос тегов между текстом и YAML
  diff.js                 построчное сравнение для предпросмотра изменений
    refactor.js           применение всей очереди к одному файлу
  modals/                 просмотр заметки, подтверждения (выбор заметок, diff), отчёт
  view/
    tag-auditor-view.js   экран: жизненный цикл, шапка, перерисовка, ленивые превью
    audit-page.js         страница «Аудит тегов»
    bulk-page.js          страница «Заметки по датам»
```

Крупные классы разделены на файлы через миксины: методы из `plugin/*.js` и `view/*-page.js` подмешиваются в прототип функцией `applyMixins`. Конструктор и `onload()` / `onunload()` плагина вынесены в `initState()`, `start()` и `stop()` из `plugin/core.js`. Новый файл в `src/` подхватывается автоматически, достаточно подключить его через `require` там, где он нужен.

## Функциональность

- Поиск тегов из Markdown и YAML-фронтматтера `tag` / `tags`.
- Просмотр заметок с отрендеренным Markdown-фрагментом, а не исходным синтаксисом.
- Сортировка тегов по названию, по дате создания заметки и по количеству заметок.
- Переименование, удаление, снятие маркировки выбранного тега и добавление нескольких новых тегов в заметки, где встречается выбранный тег, — через общую очередь и подтверждение. При снятии маркировки `#привет` визуально остаётся `#привет`, а символ `#` экранируется обратным слешем (`\#привет`) по синтаксису Markdown Obsidian, поэтому это обычный текст; соответствующая запись удаляется из YAML `tag` / `tags`.
- Предпросмотр карточки открывает заметку в новой вкладке.
- Пакетный отчёт и отмена последней операции.
- Настройки лимита предпросмотра, регистра, игнорируемых папок и YAML-атрибута даты создания. Пустой атрибут использует дату создания файла; при заданном атрибуте значения читаются из YAML.

В режиме сортировки по дате тег получает самую позднюю дату создания среди заметок, где он встречается. Источник даты задаётся в настройках YAML-атрибутом; если поле пустое, используется время создания файла. Заметки без корректного YAML-значения при заданном атрибуте учитываются как без даты и не подменяются временем изменения.

Порог упоминаний в каталоге сравнивается с количеством заметок, в которых найден тег. Пустое значение или 0 показывает все теги.

Перед массовой операцией рекомендуется проверить работу на копии хранилища.


### Форматы дат для сортировки

Поле YAML, заданное в настройках, поддерживает ISO (`2012-10-12`, дата/время), числовые форматы (`12.10.2012`, `12/10/2012`, `2012/10/12`), текстовые названия месяцев на русском, английском, украинском, белорусском, польском, немецком, французском, испанском, португальском, итальянском, нидерландском, скандинавских, турецком, греческом, арабском и тайском языках, а также форматы `2012年10月12日` и `2012년 10월 12일`. Тайские годы Buddhist Era также преобразуются в григорианские, если дата содержит тайское название месяца. Текстовые месяцы распознаются независимо от регистра и диакритики. Для числовых дат с косой чертой `MM/DD/YYYY` используется американский порядок, а для точек и дефисов — `DD.MM.YYYY` / `DD-MM-YYYY`; ISO-формат `YYYY-MM-DD` предпочтителен для однозначности.


## Version 1.0.10

The tag search field now has enough left/right padding to keep text clear of its icons and includes a dedicated clear (×) button. The unmark operation now writes a Markdown escape (`\#tag`) instead of an HTML entity, preserving the visible hash while preventing Obsidian from indexing the occurrence as a tag. The matching YAML `tag` / `tags` entry is still removed.


## Version 1.0.11

В карточку списка тегов добавлена буквенная навигация. Отображаются только буквы, с которых начинаются теги в текущем отфильтрованном списке; регистр не учитывается. Нажатие на букву плавно прокручивает список к первому тегу, начинающемуся с этой буквы.


## Version 1.0.12

Добавлено пакетное добавление нескольких тегов к заметкам, содержащим выбранный тег. Новые теги можно вводить через пробелы, запятые или переносы строк. Если исходный тег находится в YAML `tag` / `tags`, существующее поле расширяется с сохранением других значений и без дублирования тегов. Если исходный тег находится в тексте, новая строка тегов добавляется в конец каждой записи, содержащей исходный тег, перед ближайшим разделителем Markdown `---` либо в конец последней записи. Разделители, переводы строк и кодовые блоки сохраняются. Добавления можно комбинировать с другими действиями в очереди и отменить последнюю пакетную операцию.

## Version 1.0.13

Добавлена вкладка «Массовое управление». На ней можно отфильтровать Markdown-заметки по диапазону дат создания (YAML-свойство из настроек или дата создания файла), выбрать все отображаемые заметки либо снять выделение, просмотреть кратко отрендеренный Markdown, увидеть теги каждой заметки и открыть её в отдельной вкладке. Для выбранных заметок поддерживаются операции добавления нескольких тегов, переименования нескольких тегов по строкам `старый -> новый` и удаления нескольких тегов. Перед записью показывается подтверждение, затем отчёт. Последний пакет доступен для отмены.

### v1.0.28 — предпросмотр изменений, записи, перенос тегов, фильтры, статистика, телефон

- **Предпросмотр изменений.** В окнах подтверждения обеих вкладок у каждой заметки есть кнопка изменений, а над списком — «Показать изменения» для всех видимых строк. Изменения показаны построчно: удалённые строки красным, добавленные зелёным, изменённая часть строки подсвечена, рядом счётчик «+N −M» или «без изменений». Ничего не записывается, пока не нажата кнопка «Применить». Окно подтверждения «Заметок по датам» тоже получило список заметок с галочками, фильтром и «Выбрать все / Снять все».
- **Выбор записей внутри заметки.** Если в заметке несколько записей, разделённых `---` (экспорты ЖЖ, Telegram), окно просмотра показывает их по отдельности с галочками, кнопками «Все записи» и «Снять все» и пометкой записей с текущим тегом. Операции затрагивают только отмеченные записи, свойства YAML при этом не меняются. На карточке появляется значок «Записи: k из n», в очереди — пометка у числа заметок. Если заметку изменили после выбора записей и их число стало другим, она пропускается с понятной ошибкой в отчёте.
- **Перенос тегов между текстом и YAML.** На вкладке «Заметки по датам» добавлены две операции: «Перенести теги из текста в свойства (YAML)» и «Перенести теги из свойств (YAML) в текст». Можно перенести все теги или только перечисленные. Строки, где были только теги, удаляются; если у заметки нет свойства `tags`, оно создаётся. Если YAML заметки не читается, она не меняется, так что теги не теряются.
- **Фильтры «Заметок по датам».** Добавлены папка (с подпапками), теги («Любые», «Без тегов», «Есть все теги из списка», «Есть любой тег из списка»), исключение заметок с тегами и поиск по названию и тексту заметки. Теги вводятся плашками с автодополнением.
- **Статистика по годам.** В карточке тега — диаграмма числа заметок по годам по выбранному источнику даты. Клик по году открывает «Заметки по датам» с этим годом и тегом.
- **Быстрый каталог и телефон.** Каталог тегов отрисовывается порциями по 250 при прокрутке, поиск срабатывает после паузы в наборе, переход по букве дорисовывает нужную часть. На узких экранах всё выстраивается в одну колонку, вкладки занимают всю ширину, окна растянуты на весь экран. На сенсорных экранах увеличены зоны нажатия.
- Если после удаления тегов фронтматтер остался пустым, блок `---` удаляется целиком. Удаление нескольких тегов в конце строки больше не оставляет пробел.

### v1.0.27 — две зоны клика в карточке заметки

На обеих вкладках карточка заметки делится на две зоны. Шапка (название, путь, дата) переключает галочку выбора. Текст (и теги на вкладке «Заметки по датам») открывает заметку в окне. Зоны подсвечиваются при наведении, у текста курсор-лупа. Внешние ссылки в тексте открываются как обычно. С клавиатуры: пробел — выбрать, Enter — открыть.

### v1.0.26 — одинаковый выбор заметок на обеих вкладках

На вкладке «Заметки по датам» над карточками теперь те же элементы, что и на «Аудите тегов»: кнопки «Выбрать все» и «Снять все» с иконками, счётчик «Выбрано N из M» и подсказка. Кнопки неактивны, когда действие ничего не изменит: всё уже выбрано или ничего не выбрано.

### v1.0.25 — все теги в окне просмотра

Окно просмотра заметки показывает все её теги: из свойств YAML `tag` / `tags` и из текста. Теги читаются из самого файла, поэтому видны и для заметок из игнорируемых папок, и при устаревшем индексе. Теги из YAML помечены «YAML» (или «YAML + текст»), текущий тег выделен. Теги в коде, экранированные `\#`, ссылки вида `[[#Раздел]]` и чисто числовые `#2024` тегами не считаются, как и в Obsidian.

### v1.0.24 — выбор заметок на обеих вкладках, просмотр в окне, источник даты

- **Вёрстка.** Правая колонка «Аудит тегов» стала единым столбцом: высокий каталог тегов больше не растягивает сетку и не отодвигает «На изменение» вниз. Буквенная навигация занимает одну прокручиваемую строку.
- **Просмотр заметки в окне.** Клик по карточке заметки на обеих вкладках и в окне подтверждения открывает заметку по центру экрана с затемнением. Окно показывает отрендеренный текст с подсвеченным тегом, дату, теги, переключатель «Изменять эту заметку» и кнопку «Открыть во вкладке». Внутренние ссылки открываются в новой вкладке.
- **Выбор заметок на вкладке «Аудит тегов».** У каждой заметки выбранного тега есть галочка, а над списком — «Выбрать все», «Снять все» и счётчик «Выбрано N из M». Переименование, удаление, снятие # и добавление тегов ставятся в очередь только для отмеченных заметок; в очереди это видно как «N из M заметок». Окно подтверждения позволяет дополнительно сузить выбор.
- **Выбор заметок на вкладке «Заметки по датам».** Над карточками есть «Выбрать все» (с промежуточным состоянием), «Снять выделение» и счётчик «Выбрано N из M». У каждой карточки — галочка и дата.
- **Фильтр по датам.** Добавлен выбор источника даты прямо на вкладке: дата создания файла, дата изменения файла или свойство YAML. Найденные в заметках свойства с датами предлагаются автоматически, с числом заметок. Под полями показано, у скольких заметок есть дата и в каком диапазоне. Если по дате создания файла ничего не находится, плагин подсказывает свойство YAML: Syncthing и копирование часто сбрасывают дату создания файла на дату синхронизации. Тот же выбор доступен в настройках («Дата файла, если YAML-атрибут не задан»).

### v1.0.23 — работа без папки src/

### v1.0.22 — выбор заметок при применении очереди, без сборщика

- В окне «Применить изменения» на вкладке «Аудит тегов» есть список всех затронутых заметок с галочками. По умолчанию выбраны все. Кнопки «Выбрать все» и «Снять все» действуют на заметки, видимые с учётом фильтра по названию или пути. У каждой заметки показаны найденные в ней теги из очереди и кнопка открытия в новой вкладке. Изменения записываются только в выбранные заметки.

### v1.0.20 — исправления и оптимизация

Исправлено:

- Добавление тегов в пустое поле `tags:` больше не ломает фронтматтер (раньше получалось `tags:[, "тег"]`): создаётся обычный список.
- YAML-списки без отступа (`tags:` + `- тег`) теперь корректно переименовываются, удаляются и дополняются; раньше переименование их пропускало, а добавление ломало YAML.
- Строка `tags: a, b` (и `tags: a b`) распознаётся как несколько тегов — при сканировании, переименовании, удалении и добавлении.
- Переименование в тег, который уже есть в том же YAML-списке, больше не создаёт дубль (`[b, b]` → `[b]`).
- «Всегда добавлять в атрибуты» для заметки с пустым фронтматтером (`---` / `---`) больше не создаёт второй блок фронтматтера.
- `#` внутри вики-ссылок (`[[#Раздел]]`, `[[заметка#Раздел]]`) и адресов Markdown-ссылок больше не считается тегом и не изменяется.
- Удаление тега не оставляет двойных пробелов и пробелов в конце строки.
- Перед применением очереди индекс тегов пересканируется, чтобы учесть заметки, изменённые за время открытого диалога.
- При переключении учёта регистра очередь изменений очищается (раньше её ключи относились к старому режиму).
- Повторный запуск применения во время уже идущей операции блокируется.
- Если выбранный тег исчез, вместо пустой карточки показывается подсказка «Выберите тег»; склонение «Выбрано N заметок» исправлено.

Оптимизация:

- Индекс тегов строится только когда экран плагина открыт; экран перерисовывается только если реально изменились теги, а не при каждом наборе текста в заметке. Скрытая вкладка перерисовывается при показе.
- Файлы, которые операция не меняет, не перезаписываются — время изменения сохраняется, Syncthing не видит лишних правок.
- Предпросмотры отрисовываются лениво, только при прокрутке к карточке; в «Заметках по датам» карточки выводятся порциями по 60 с кнопкой «Показать ещё».
- Компоненты Markdown-предпросмотров выгружаются при каждой перерисовке (раньше накапливались — утечка памяти).
- Теги заметки, даты создания и сортировка кэшируются на время одного сканирования вместо пересчёта для каждой карточки; сортировка — через `Intl.Collator`.
- Сохранение настроек пересканирует хранилище один раз после паузы ввода, а не на каждый символ.
- При перерисовке сохраняются введённое имя тега, список добавляемых тегов, фокус поля и прокрутка.
